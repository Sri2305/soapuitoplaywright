The workflow

      
Built for parity, not guesswork

      
The converter does the reliable, mechanical 80% deterministically. The judgement calls are flagged for you — never silently guessed.

    

    

      

        
1

        
Convert the structure

        
Each test suite becomes a .spec.ts, each step a test.step(), each status check a real assertion. Properties land in .env.

      

      

        
2

        
Review the flags

        
Groovy scripts and dynamic property transfers are marked // TODO and // REVIEW so a human (or Copilot) finishes them with full context.

      

      

        
3

        
Run against your API

        
Drop the files into a Playwright project, fill secrets in .env, and run npx playwright test. Compare results to ReadyAPI for parity.

Good to know

      
Questions

    

    

      
Is my XML uploaded anywhere?

      
No. Parsing and conversion run entirely in your browser with JavaScript. Nothing leaves your machine — safe for corporate code.

    

    

      
Does it handle OAuth2?

      
The generated tests use a bearerToken fixture for auth instead of hardcoding tokens. You wire your OAuth2 grant once in the auth fixture (covered in the README) and every test inherits it.

    

    

      
Why are some things flagged instead of converted?

      
Groovy scripts and dynamic property paths can't be translated mechanically without risking an assertion that passes for the wrong reason. Flagging them keeps the migration honest — you finish those with full context, or hand them to the Copilot agent.

    

    

      
Can I sell access to this?

      
The page packages your own explanation and tooling. Playwright, ReadyAPI, and Copilot are other companies' products — sell your work, don't redistribute their docs or imply endorsement, and make sure any test data you use is yours to share.
